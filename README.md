# THE 12 CHRONICLES
### A Private Travel Website for the Squad • IIT Bombay Techfest × Mumbai 2026

> *"12 Friends. One Journey. A Thousand Memories."*

**The 12 Chronicles** is a private, editorial-style trip planning site and digital journal for a verified group of friends travelling to **IIT Bombay Techfest** and exploring **Mumbai** in December 2026.

It combines a live itinerary, Mumbai explorer, shared photo gallery, trip planner, squad directory and a Treasurer-controlled shared expense ledger. Member registration, login, roles and expense data are backed by **Firebase Authentication + Firestore** in production, with an automatic local preview mode when Firebase is not configured.

## 🛠️ Technology Stack

- **Markup & Styling:** Semantic HTML5, Tailwind CSS via CDN with custom tokens, Google Fonts (`Playfair Display` + `Plus Jakarta Sans`).
- **Client Scripting:** Pure Vanilla JavaScript controllers (no framework, no build step).
- **Auth & Data:** Firebase Authentication (email/password) and Cloud Firestore using the Firebase `10.12.2` compat SDK, loaded dynamically.
- **Local Preview Fallback:** When Firebase credentials are absent, accounts are stored as SHA-256 password hashes in `localStorage`, with the same role and permission model for safe local testing.

## 🔐 Admin-Controlled Private Registration & Roles

| Role | How it is granted | Permissions |
| :--- | :--- | :--- |
| **Admin (Owner)** | Single authorized account with Firebase custom claim `admin: true` (or local setup) | Only user with access to `/admin.html`. Generates invite codes, revokes codes, reviews Treasurer applications, manages member roles, full expense write access. |
| **Treasurer** | Registers with a `CHRONICLES-T...` invite code and is approved by the Admin | Add, edit, delete, and settle shared expenses; manage expense categories. |
| **Member** | Registers with a `CHRONICLES-M...` invite code | Full private access to schedule, squad, planner, gallery, and read-only view of expense ledger. |

### Key Security Rules:
- **No Public Admin Signup:** Admin is never an option on public signup. The single Admin account is established via `functions/scripts/set-admin-claim.js` (cloud) or a secure initial setup (local).
- **Invitation-Gated Registration:** All registrations require an active, unexpired, non-revoked invitation code generated by the Admin:
  - `CHRONICLES-M...` for standard Squad Members.
  - `CHRONICLES-T...` for Treasurers.
- **Atomic Usage & Expiration:** Codes enforce usage limits (e.g. single-use) and optional expiration timestamps. Depleted, expired, or revoked codes cannot be redeemed.
- **Two-Stage Treasurer Approval:** Users registering with a Treasurer code are created with `roleStatus: "pending"` and hold normal Member access until the Admin explicitly approves them in `/admin.html`.
- **Protected Expense Ledger:** Only the Admin and Approved Treasurers can add, edit, delete, or settle expenses. Normal Members and Pending Treasurers are strictly read-only in both the UI and `firestore.rules`.

Requires Node.js for the included static server (or use any static file server).

```powershell
npm start
# or: node server.js
```

Open `http://localhost:3000`.

### Local preview mode

If `js/firebase-config.js` still contains the placeholder API key:

- Registration and login work entirely in this browser.
- Users are stored under `chronicles_users` with hashed passwords.
- The active session is stored under `chronicles_session_uid`.
- Expenses and other trip data use the existing local storage data layer.
- The navbar/auth page clearly shows **Local preview** mode.

To test real cloud behaviour, configure Firebase as described below.

## 🔥 Firebase Setup

1. Create a project at [console.firebase.google.com](https://console.firebase.google.com).
2. Enable **Authentication → Sign-in method → Email/Password**.
3. Create a **Firestore Database**.
4. Copy the web app config into `js/firebase-config.js`:

```javascript
const DEFAULT_FIREBASE_CONFIG = {
  apiKey: "YOUR_FIREBASE_API_KEY",
  authDomain: "your-project-id.firebaseapp.com",
  projectId: "your-project-id",
  storageBucket: "your-project-id.appspot.com",
  messagingSenderId: "YOUR_MESSAGING_SENDER_ID",
  appId: "YOUR_APP_ID"
};
```

You can also paste credentials at runtime using the **Firebase Connection** button in the footer or auth page. Runtime config is saved in `localStorage` and overrides the file config on that device.

5. Update `GROUP_CONFIG` in the same file:

```javascript
const GROUP_CONFIG = {
  inviteCode: "CHANGE-THIS-CODE",
  adminEmails: [
    "you@example.com",
    "co-admin@example.com"
  ],
  collections: {
    users: "users",
    expenses: "expenses",
    invites: "groupInvites",
    settings: "settings",
    explore: "exploreDestinations"
  }
};
```

6. Deploy `firestore.rules` with the Firebase CLI:

```powershell
npm install -g firebase-tools
firebase login
firebase init firestore   # choose the existing project and use firestore.rules
firebase deploy --only firestore:rules
```

### Creating the first Admin

Sign up using one of the bootstrap admin emails. `js/auth.js` assigns the Admin role automatically, and `firestore.rules` only permits that Admin bootstrap for the email list in the rules file. After the first Admin exists, they can approve Treasurer requests from **Squad → Treasurer Applications**.

### Invitation codes

- The default client-side code is `TECHFEST2026` (change it in `GROUP_CONFIG`).
- Optional Firestore-backed codes can be created in the `groupInvites` collection:

```json
{
  "active": true,
  "note": "Extra invite for a squad member"
}
```

The document ID is the code itself. Unauthenticated exact-document reads are allowed only so the registration form can validate a code; listing invite codes is Admin-only.

## 🧾 Expense Ledger Behaviour

- **Members:** read-only. They see totals, per-person averages, their own net balance, the ledger and suggested settlements.
- **Treasurer / Admin:** can add, edit and delete expenses; change payment status (`pending`, `paid`, `settled`); and manage categories.
- Expense records include audit fields: `createdBy`, `createdByName`, `createdAt`, `updatedBy`, `updatedByName`, `updatedAt`.
- Balances and minimum-transfer settlements are calculated client-side from `paidById`, `amount` and `splitBetween`.
- Firestore rules enforce the same Treasurer/Admin restrictions server-side.

---

## 🔒 Security Notes

- Never commit real Firebase credentials to a public repository if your project requires restricted access; use the runtime config dialog or deployment environment instead.
- The group invite code is a convenience gate. Real access control is enforced by Firebase Auth and Firestore rules.
- Firestore rules deny all unmatched collections with a catch-all rule.
- Profile photos are compressed to a 320px JPEG data URL before storage.
- Password reset emails require Firebase; local preview mode intentionally does not support them.
